# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

NeoForge mod (`mod_id` `cronusfantasyterrain`, package `c.cronus.fantasyterrain`) that adds a **Fantasy Regions** world preset: an infinite Overworld split into large seeded, rounded-hexagon regions (~1700 blocks centre to side, centres ~3800 apart, belts ~400 blocks foot to foot) separated by alpine mountain border belts. Targets Minecraft **26.3**, NeoForge **26.3.0.43-beta**, Java **25** (versions in `gradle.properties`). The Nether/End are vanilla. `CronusFantasyTerrain.java` only registers the worldgen (`RegionWorldgen.register`); the MDK example block/item/tab and the earlier Test World preset were removed in `update_03.01.01`.

## Commands

Windows shell; use `gradlew.bat` (or `./gradlew` from Git Bash).

- `gradlew.bat build` – compile, package, and run all checks (`check` depends on the six test tasks below). CI (`.github/workflows/build.yml`) runs `./gradlew build` on JDK 25.
- `gradlew.bat regionLayoutTest` – standalone geometry checks (`RegionLayoutTest.main`, 30,000 sampled positions).
- `gradlew.bat borderPaletteTest` – border material palette checks (`BorderPaletteTest.main`).
- `gradlew.bat everwinterTest` – Everwinter terrain/material checks plus data wiring (pool slot vs. `FrozenLand`, shared `region_size`/`border_width`).
- `gradlew.bat howlingCanyonTest` – Howling Canyon checks (`HowlingCanyonTest.main`): river per district (open ends, ice to the edge, open banks, uneven bends), massifs broken by gaps and saddles, natural shapes (off-centre tops, irregular outlines, varied sizes/spacing), glaciers from the mountains (high, stepped, ice on the rock within reach, open passages), untouched borders/biome edge/Everwinter columns, nothing below Y=63, depth/floor/river/cliffs/benches, materials, wiring.
- `gradlew.bat biomeDistrictTest` – biome district checks (`BiomeDistrictTest.main`): preset pools have 4–6 distinct biomes, router codes round-trip, and in every scanned region each pool biome forms exactly one connected district of reasonable size (grid fragments are re-traced block by block).
- `gradlew.bat borderFeatureTest` – Groovy task in `build.gradle` that enforces the border biome feature whitelist (only `cronusfantasyterrain:border/ore_*`, deepslate ores replacing only deepslate/tuff, `discard_chance_on_air_exposure == 1.0`).
- `gradlew.bat regionPreview` – renders `build/reports/regions/preview.png`, `border-terrain.png`, `border-rim.png`, `border-volume.png`, `basin-section.png`, `border-snow.png`, `biome-districts.png` (layout seed 12345; software previews, not in-game).
- `gradlew.bat everwinterPreview` – renders `build/reports/biomes/everwinter-map.png`, `everwinter-view.png`, `everwinter-closeup.png`, `everwinter-seracs.png`, `everwinter-fringe.png` and `everwinter-fringe-map.png`.
- `gradlew.bat howlingCanyonPreview` – renders `build/reports/biomes/howling-canyon-map.png`, `howling-canyon-view.png`, `howling-canyon-rim.png`, `howling-canyon-mouth.png`, `howling-canyon-overview.png`, `howling-canyon-cliffs.png`, `howling-canyon-glacier.png` (perspective views), `howling-canyon-section.png` and `howling-canyon-glacier-section.png` (real layout, seed 12345).
- `gradlew.bat runClient` / `runServer` / `runGameTestServer` / `runData` – NeoForge run configs (`run/` is the game dir).

Tests are **not JUnit**: each is a `public static void main` under `src/test/java` wired up as a `JavaExec` task, failing via thrown exceptions. `test` has `failOnNoDiscoveredTests = false`. To add a test, write a `main` class and register a `JavaExec` task + `check` dependency in `build.gradle` following the existing pattern.

## Architecture

World generation is mostly data-driven JSON wired to a few custom registered codecs (`worldgen/RegionWorldgen.java` registers them plus the chunk event listeners):

- **`RegionLayout`** – pure Java, no Minecraft dependencies. Owns the seeded horizontal region partition (`sample(x,z)` → region id 0–4 + border mask 0–1; rounded-hexagon regions (`HEX` sharpness plus small per-region `LOBES`/`OVAL`, radius cached per cell and trimmed so every rim stays `MIN_GAP`/2 behind the halfway line to each neighbour) on a jittered hex grid; each position belongs to the region with the nearest jagged rim, and the edge distance is measured from that rim; `rimReach` then shifts the edge distance so the whole mountain front pushes up to `RIM_REACH` blocks into the region in broad lobes, sampled at the radial rim point so no islands form) and the terrain column (`surfaceHeight`, `terrainColumn(...).density(y)`) including one broad mountain range (smooth noise plus moderate ridged crests around `RANGE_CENTER` = 212, rare summits up to `PEAK_LIMIT` and rare valleys down to `MASSIF_FLOOR` = 150) reached by a short ramp (`RAMP_START`..`RAMP_END` of the border width). Because it is MC-free, the standalone tests and previews exercise it directly.
- **`RegionFunction`** – a `DensityFunction` (`cronusfantasyterrain:region`) wrapping `RegionLayout`, with `output` = `region | border | height | density | exterior_floor | basin_floor`. Seed derived from `context.createRandom("cronusfantasyterrain:region_layout")` so all outputs share identical geometry independent of chunk order.
- **`BiomeDistricts`** – pure Java. Splits every region into one district per pool biome, so each pool biome appears exactly once per region: a Voronoi diagram of 4–6 sites on a seeded, off-centre ring around the region centre, computed in `RegionLayout`'s bent plane (`Sample.localX/localZ`) after a radial `tanh` compression (so boundaries cross the mountain foot steeply instead of leaving slivers in rim bays) plus a gentle warp; biome order is a seeded shuffle per region (`Sample.cellX/cellZ`). `code(sample)` packs the slots for pool sizes 4, 5 and 6 into one integer (mixed radix, 0–119); `slot(code, size)` unpacks it. `District.edge` is the distance to the nearest other district (0 on a boundary) for fading biome terrain.
- **`BiomeTerrainFunction`** (`cronusfantasyterrain:biome_terrain`, outputs `density | height | everwinter | feature | ice_base | district | fringe | canyon | canyon_feature | canyon_bed`) – rebuilds the same `RegionLayout` and `BiomeDistricts` (seed `cronusfantasyterrain:biome_districts`), repeats the biome source's tests (region, border mask, district slot) and adds biome relief (`EverwinterTerrain`) scaled by a weight that is 0 at the biome edge (`districtWeight`) and in every border-touched column. Output `district` (`density_function/region_districts.json`) is the packed district code for the router. Each output compiles its own sampler, so columns are shared through a per-thread cache keyed by the seeds. Where the weight is 0 it equals `region_terrain` exactly, so borders/basin stay untouched. `EverwinterMaterialRule` (`cronusfantasyterrain:everwinter_palette`) applies `EverwinterPalette` from Y=0 up in Everwinter columns. Everwinter is Frozen Wastes pool slot `FrozenLand.EVERWINTER_SLOT` = 2 of `POOL_SIZE` = 5. Its relief (rolling ground, snow piles, big snow/ice hills, ice cliffs, crevasses, serac fields, spires, outcrops) is a heightmap; feature codes and `ice_base` (bed of the glacier ice sheet, kept below every nearby cut so walls are ice) drive the palette, and cuts never go below `LOWEST_FLOOR` = 66 so they stay dry. Generated snow layer blocks were tried and rejected by the user (decision 17); keep full blocks plus vanilla `freeze_top_layer`, which also blends the biome edges. Serac fields are groups of 4-7 plates (tilted pieces of the ground itself: low end sunk below it, high end a sheer face) that never touch directly: between neighbours either a deep tear 1-2 blocks wide or 16-36 blocks of plain snow ground with only gentle rises (decisions 21-23; the user rejected both sunken rubble and terrace steps there, keep it plain; `everwinterTest` checks both and that no two plates share a block edge). Everwinter has no natural water: the preset has no aquifers (every cave below sea level floods, world-wide), so `EverwinterDryFeature` (`everwinter/dry`, last feature step) drains Everwinter columns and seals neighbouring water with packed ice; keep `spring_water` out of the biome. `EverwinterGroups` places two or three fields per Everwinter district (searched once per region from `RegionLayout.siteX/siteZ`, which are package-private only for this; cached, one instance per setup in `BiomeTerrainFunction.GROUPS`); `EverwinterTerrain.column(x, z, base, weight)` without groups uses a 1000-block grid for tests and previews.
- **Howling Canyon** (`cronusfantasyterrain:howling_canyon`, Frozen Wastes slot `FrozenLand.HOWLING_CANYON_SLOT` = 4, replaced the Frozen River placeholder): `BiomeTerrainFunction` asks `HowlingCanyonColumns` first; only non-canyon columns go to `EverwinterColumns` (canyon columns report the plain Everwinter outputs it would give), so Everwinter's columns are bit-identical. `HowlingCanyonTerrain` (decision 29; the user rejected continuous walls along the river, never go back to them): open ground at `FLOOR_Y` with the river, and separate glacier massifs, overhauled to natural shapes on request (decision 32, 2026-10-30): one site anywhere in each `MASSIF_CELL` = 300 cell (`massif`: radius varying with direction, `shape`, plus `lobes`; ownership by distance minus `OWNERSHIP` x radius so dividing lines curve; `Sites.divide` is a distance-like measure; cut back `GAP_MIN`-`GAP_MAX` from every neighbour with `cornerMin` corners; narrow parts pull back via `pullBack`, so no needles, fins or lone knobs). Height climbs from the outline (first cliff) to an off-centre summit (`Summits`, cached per massif; about 40% with a lower second summit) as inside / (inside + distance to summit) (`climb`), never gentler than `MIN_RISE` (keeps cliffs sheer), the summit's tier limited by `RATE` from its room (`summitTier`: a squeezed massif gets fewer tiers, not steeper walls); `terrace` (3 tiers of 18-28 blocks, drifting about 25% across the land, plus a summit tier) makes benches and risers; each cliff is a flat wall in 2 or 3 even steps (`CLIFF` = 0.25 share of the band, `LEDGE`, `cliffSteps` per massif and tier; decision 30: the user rejected random/jagged columns, keep walls flat with simple steps). No fine wobble on cliff lines (it frayed narrow ridge crests). Most gaps are ground, the rest saddles (passes) at tier 1 or 2, only between massifs that face each other (kept a gap away from every third site's ground). Gaps are measured against every neighbouring site and each saddle pass depends only on its two massifs (`pass1`/`pass2`), never on the owning cell, and rises in the same stepped cliffs: owner-dependent or hard-edged fields made tall flat walls before (decision 30); `howlingCanyonTest` fails on any drop over 20 blocks. Toward the biome edge tiers are cut first and then scaled by the weight (cliffs stay sheer). Toward the border mountains (decision 33) `glacier` replaces the fade: from `GLACIER_START` the massif's outline reaches out (`massif(x, z, outward)`, up to `GLACIER_REACH`, never into neighbours), its field rises from its top tier by `GLACIER_RISE` towards the mountains (sides `WALL_RISE`), terraced like the rest; on the mountain a sheet (`SHEET_MIN`-`SHEET_MAX`) on the rock thins out by `CLIMB_MIN`-`CLIMB_MAX`; `HowlingCanyonColumns` takes the higher of canyon and glacier. The glaciers stay separate tongues: merging them into one continuous glacier wall along the mountains was rejected (2026-10-30), never do that. The river is never closed off (decision 28): `HowlingCanyonCourses` (one per setup in `BiomeTerrainFunction.COURSES`, cached per region) traces it through the whole district and out at both ends (preferring exits into neighbouring biomes, `opensToBiome`; bends of uneven length from two noise octaves plus a drift, `Meander`, never a sine), and the ground rises smoothly to the neighbouring ground (`floorRise`). The river stops at the biome boundary; extending it into other biomes needs the user's OK. Ground `FLOOR_Y` = 66, surface clamped to `LOWEST_SURFACE` = 64 (sea level 63, no aquifers: anything lower floods). Weights: `DISTRICT_FADE` = 220, `EDGE_FADE` = 160; zero in every border column. Materials: `HowlingCanyonMaterialRule` (`howling_canyon_palette`) from Y=0 up: glacier ice strata above the `canyon_bed` output, snow cover on gentle ground, river floes, stone/deepslate below. Biome file has no water springs/lakes and no ravine carver.
- **Noise router channel repurposing** (`noise_settings/regions.json`): `temperature` = region id, `erosion` = border mask, `vegetation` = packed biome-district code (`region_districts`), `final_density` = `biome_terrain`, `chunk_surface_level` = `biome_height`. These are *not* climate values.
- **`RegionBiomeSource`** (`cronusfantasyterrain:regions`) reads those channels: erosion > `RegionLayout.BORDER_THRESHOLD` (0.12) → `mountain_biome`; otherwise temperature picks the region pool and `BiomeDistricts.slot(vegetation, pool size)` picks the biome. Pools (4–6 **distinct** biomes each, enforced by the codec; currently mostly vanilla placeholders) are defined in `world_preset/regions.json`; pool order only fixes slot numbers, the district layout per region is shuffled. The codec has five hard-coded pool fields; adding a region requires changing the codec, `RegionLayout.REGION_COUNT`, `RegionFunction.range()`, the clamp in the resolver, and the preset.
- **Border materials**: `material_rule/regions.json` → bedrock floor, `material_rule/region_border.json`, `material_rule/region_basin.json`, vanilla copper/iron ore veins, `material_rule/everwinter.json`, `material_rule/howling_canyon.json`, then vanilla overworld. `BorderMaterialRule` (`cronusfantasyterrain:border_palette`) claims columns whose border mask > `BORDER_THRESHOLD` (per column, not the fuzzy per-block biome, which left stone inside mountains) and uses the `exterior_floor` output (lowest neighboring surface) to distinguish outdoor faces from buried rock; `BorderPalette` picks deepslate below / patchy snow outdoors around a wandering snowline (average `SNOW_LINE = 214`, `SNOW_BAND = 36`, fading in from Y=179, solid from Y=264; steep faces shed snow), deepslate with ~4% tuff underground.
- **Deepslate basin ("cauldron")**: `BasinMaterialRule` (`cronusfantasyterrain:region_basin`) paints deepslate from Y=0 up to `RegionLayout.basinFloor` (`basin_floor` output) in non-border columns: the floor meets the surface at the mountain foot and curves to Y=0 within `BASIN_REACH` = 384 blocks, so foothills/interiors keep vanilla stone above a deepslate bowl. Below Y=0 is left to vanilla (iron veins).
- **`BorderChunkMaterials`** – queues newly generated chunks on `ChunkEvent.Load`, processes them on server tick (8 per tick, drained on shutdown) to re-apply the palette after neighbor feature spill-over. Only acts when the generator uses `cronusfantasyterrain:regions` noise settings; never rewrites old chunks. Do not query the level/neighbors inside the load callback.

### Invariants

- `region_size` and `border_width` must be **identical** in every `cronusfantasyterrain:region` and `cronusfantasyterrain:biome_terrain` density function (`region_id`, `region_border`, `region_height`, `region_terrain`, `border_exterior_floor`, `region_basin_floor`, `biome_terrain`, `biome_height`, `everwinter_*`, `howling_canyon_*`), or terrain and region ownership desynchronize (`everwinterTest` checks this).
- The Frozen Wastes pool in `world_preset/regions.json` must match `FrozenLand.POOL_SIZE`/`EVERWINTER_SLOT`/`HOWLING_CANYON_SLOT` (checked by `everwinterTest` and `howlingCanyonTest`). Every pool must list 4–6 biomes, each at most once (`BiomeDistricts.MIN_BIOMES`/`MAX_BIOMES`; codec and `biomeDistrictTest`). Biome terrain stays zero in border-touched columns unless a biome is meant to change its border (decision 34): Everwinter's relief and glacier tongues continue onto the mountain foot (decisions 24-25, `everwinterTest`), Howling Canyon's glaciers lie on the mountain slope (decision 33, `howlingCanyonTest`).
- Generation parameters are saved into worlds; verify changes in a **fresh** Fantasy Regions world.
- The code/data key for Scorched Lands is still `ember_lands`; the rename is documentation-only.
- `FrozenLand.REGION_INDEX` identifies the Frozen Wastes pool index.

## Standing user decisions

- **Border freeze lifted** (2026-10-30, decision 34; frozen 2026-10-16 to 2026-10-30, decision 1). The user: "Remove the block from the border region so that the border can be edited however it needs to be for the biomes to look proper." The borders (mountain shape, partition, materials, snow, basin, border biome) may be changed wherever a biome needs it to look right; keep the existing border design as the default elsewhere and mention every border change in the summary. Border changes so far: Everwinter's terrain runs up the mountain foot (decisions 24-25, column logic in `EverwinterColumns`: `borderReach`, `edgeGlacier`; taken-over border columns report `everwinter` = 1, so `BorderMaterialRule` steps aside above the ice-sheet bed and `BorderChunkMaterials` skips them; patchy frost beyond via `BorderPalette.selectFringe`); Howling Canyon's glaciers come down from the mountains (decision 33, `HowlingCanyonTerrain.glacier`: ice on the unchanged rock, border columns it lies on report `canyon` = 1, `BorderMaterialRule` steps aside above `canyon_bed`, `BorderChunkMaterials` skips them). A broken-up icefall with broken-open rock and one continuous glacier wall along the mountains were both rejected there; never bring them back. Never add isolated point features on untouched ground; extend the biome's own terrain.
- **Everwinter's terrain is frozen** (2026-10-17, decision 26). Do not change anything about it (`EverwinterTerrain`, `EverwinterColumns`, `EverwinterGroups`, `EverwinterPalette`, its border transition, its biome file) unless the user specifically asks. If a change involves other biomes (pool slots, the shared district layout, shared code that would alter another biome's output), tell the user before making it.
- **Terrain looks natural, never mathematical** (2026-10-27, decision 31). All newly generated terrain, in every biome: no symmetrical shapes, perfect circles, squares, ellipses or regular polygons (outlines, tops, plateaus), no ruler-straight lines, no evenly spaced rings or grid-like repetition. Vary outlines by direction and at several scales, put tops off-centre, give slopes different steepness on different sides, vary size, height and spacing per landform. "Random" means natural and irregular, not noisy or jagged: where the user asks for something plain (decisions 23 and 30) keep it plain, but its outline still follows natural lines. Does not authorize changes to frozen terrain.
- Border biome features are restricted to the custom deepslate ore placements; no decorative blocks, vegetation, or other features (enforced by `borderFeatureTest`).
