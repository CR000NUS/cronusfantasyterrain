# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

NeoForge mod (`mod_id` `cronusfantasyterrain`, package `c.cronus.fantasyterrain`) that adds a **Fantasy Regions** world preset: an infinite Overworld split into large seeded, rounded-hexagon regions (~1700 blocks centre to side, centres ~3800 apart, belts ~400 blocks foot to foot) separated by alpine mountain border belts. Targets Minecraft **26.3**, NeoForge **26.3.0.43-beta**, Java **25** (versions in `gradle.properties`). The Nether/End are vanilla. The example block/item/tab in `CronusFantasyTerrain.java` are leftover MDK template code.

## Commands

Windows shell; use `gradlew.bat` (or `./gradlew` from Git Bash).

- `gradlew.bat build` – compile, package, and run all checks (`check` depends on the five test tasks below). CI (`.github/workflows/build.yml`) runs `./gradlew build` on JDK 25.
- `gradlew.bat regionLayoutTest` – standalone geometry checks (`RegionLayoutTest.main`, 30,000 sampled positions).
- `gradlew.bat borderPaletteTest` – border material palette checks (`BorderPaletteTest.main`).
- `gradlew.bat everwinterTest` – Everwinter terrain/material checks plus data wiring (pool slot vs. `FrozenLand`, shared `region_size`/`border_width`).
- `gradlew.bat biomeDistrictTest` – biome district checks (`BiomeDistrictTest.main`): preset pools have 4–6 distinct biomes, router codes round-trip, and in every scanned region each pool biome forms exactly one connected district of reasonable size (grid fragments are re-traced block by block).
- `gradlew.bat borderFeatureTest` – Groovy task in `build.gradle` that enforces the border biome feature whitelist (only `cronusfantasyterrain:border/ore_*`, deepslate ores replacing only deepslate/tuff, `discard_chance_on_air_exposure == 1.0`).
- `gradlew.bat regionPreview` – renders `build/reports/regions/preview.png`, `border-terrain.png`, `border-rim.png`, `border-volume.png`, `basin-section.png`, `border-snow.png`, `biome-districts.png` (layout seed 12345; software previews, not in-game).
- `gradlew.bat everwinterPreview` – renders `build/reports/biomes/everwinter-map.png`, `everwinter-view.png`, `everwinter-closeup.png`, `everwinter-seracs.png`, `everwinter-fringe.png` and `everwinter-fringe-map.png`.
- `gradlew.bat runClient` / `runServer` / `runGameTestServer` / `runData` – NeoForge run configs (`run/` is the game dir).

Tests are **not JUnit**: each is a `public static void main` under `src/test/java` wired up as a `JavaExec` task, failing via thrown exceptions. `test` has `failOnNoDiscoveredTests = false`. To add a test, write a `main` class and register a `JavaExec` task + `check` dependency in `build.gradle` following the existing pattern.

## Architecture

World generation is mostly data-driven JSON wired to a few custom registered codecs (`worldgen/RegionWorldgen.java` registers them plus the chunk event listeners):

- **`RegionLayout`** – pure Java, no Minecraft dependencies. Owns the seeded horizontal region partition (`sample(x,z)` → region id 0–4 + border mask 0–1; rounded-hexagon regions (`HEX` sharpness plus small per-region `LOBES`/`OVAL`, radius cached per cell and trimmed so every rim stays `MIN_GAP`/2 behind the halfway line to each neighbour) on a jittered hex grid; each position belongs to the region with the nearest jagged rim, and the edge distance is measured from that rim; `rimReach` then shifts the edge distance so the whole mountain front pushes up to `RIM_REACH` blocks into the region in broad lobes, sampled at the radial rim point so no islands form) and the terrain column (`surfaceHeight`, `terrainColumn(...).density(y)`) including one broad mountain range (smooth noise plus moderate ridged crests around `RANGE_CENTER` = 212, rare summits up to `PEAK_LIMIT` and rare valleys down to `MASSIF_FLOOR` = 150) reached by a short ramp (`RAMP_START`..`RAMP_END` of the border width). Because it is MC-free, the standalone tests and previews exercise it directly.
- **`RegionFunction`** – a `DensityFunction` (`cronusfantasyterrain:region`) wrapping `RegionLayout`, with `output` = `region | border | height | density | exterior_floor | basin_floor`. Seed derived from `context.createRandom("cronusfantasyterrain:region_layout")` so all outputs share identical geometry independent of chunk order.
- **`BiomeDistricts`** – pure Java. Splits every region into one district per pool biome, so each pool biome appears exactly once per region: a Voronoi diagram of 4–6 sites on a seeded, off-centre ring around the region centre, computed in `RegionLayout`'s bent plane (`Sample.localX/localZ`) after a radial `tanh` compression (so boundaries cross the mountain foot steeply instead of leaving slivers in rim bays) plus a gentle warp; biome order is a seeded shuffle per region (`Sample.cellX/cellZ`). `code(sample)` packs the slots for pool sizes 4, 5 and 6 into one integer (mixed radix, 0–119); `slot(code, size)` unpacks it. `District.edge` is the distance to the nearest other district (0 on a boundary) for fading biome terrain.
- **`BiomeTerrainFunction`** (`cronusfantasyterrain:biome_terrain`, outputs `density | height | everwinter | feature | ice_base | district | fringe`) – rebuilds the same `RegionLayout` and `BiomeDistricts` (seed `cronusfantasyterrain:biome_districts`), repeats the biome source's tests (region, border mask, district slot) and adds biome relief (`EverwinterTerrain`) scaled by a weight that is 0 at the biome edge (`districtWeight`) and in every border-touched column. Output `district` (`density_function/region_districts.json`) is the packed district code for the router. Each output compiles its own sampler, so columns are shared through a per-thread cache keyed by the seeds. Where the weight is 0 it equals `region_terrain` exactly, so borders/basin stay untouched. `EverwinterMaterialRule` (`cronusfantasyterrain:everwinter_palette`) applies `EverwinterPalette` from Y=0 up in Everwinter columns. Everwinter is Frozen Wastes pool slot `FrozenLand.EVERWINTER_SLOT` = 2 of `POOL_SIZE` = 5. Its relief (rolling ground, snow piles, big snow/ice hills, ice cliffs, crevasses, serac fields, spires, outcrops) is a heightmap; feature codes and `ice_base` (bed of the glacier ice sheet, kept below every nearby cut so walls are ice) drive the palette, and cuts never go below `LOWEST_FLOOR` = 66 so they stay dry. Generated snow layer blocks were tried and rejected by the user (decision 17); keep full blocks plus vanilla `freeze_top_layer`, which also blends the biome edges. Serac fields are groups of 4-7 plates (tilted pieces of the ground itself: low end sunk below it, high end a sheer face) that never touch directly: between neighbours either a deep tear 1-2 blocks wide or 16-36 blocks of plain snow ground with only gentle rises (decisions 21-23; the user rejected both sunken rubble and terrace steps there, keep it plain; `everwinterTest` checks both and that no two plates share a block edge). Everwinter has no natural water: the preset has no aquifers (every cave below sea level floods, world-wide), so `EverwinterDryFeature` (`everwinter/dry`, last feature step) drains Everwinter columns and seals neighbouring water with packed ice; keep `spring_water` out of the biome. `EverwinterGroups` places two or three fields per Everwinter district (searched once per region from `RegionLayout.siteX/siteZ`, which are package-private only for this; cached, one instance per setup in `BiomeTerrainFunction.GROUPS`); `EverwinterTerrain.column(x, z, base, weight)` without groups uses a 1000-block grid for tests and previews.
- **Noise router channel repurposing** (`noise_settings/regions.json`): `temperature` = region id, `erosion` = border mask, `vegetation` = packed biome-district code (`region_districts`), `final_density` = `biome_terrain`, `chunk_surface_level` = `biome_height`. These are *not* climate values.
- **`RegionBiomeSource`** (`cronusfantasyterrain:regions`) reads those channels: erosion > `RegionLayout.BORDER_THRESHOLD` (0.12) → `mountain_biome`; otherwise temperature picks the region pool and `BiomeDistricts.slot(vegetation, pool size)` picks the biome. Pools (4–6 **distinct** biomes each, enforced by the codec; currently mostly vanilla placeholders) are defined in `world_preset/regions.json`; pool order only fixes slot numbers, the district layout per region is shuffled. The codec has five hard-coded pool fields; adding a region requires changing the codec, `RegionLayout.REGION_COUNT`, `RegionFunction.range()`, the clamp in the resolver, and the preset.
- **Border materials**: `material_rule/regions.json` → bedrock floor, `material_rule/region_border.json`, `material_rule/region_basin.json`, vanilla copper/iron ore veins, `material_rule/everwinter.json`, then vanilla overworld. `BorderMaterialRule` (`cronusfantasyterrain:border_palette`) claims columns whose border mask > `BORDER_THRESHOLD` (per column, not the fuzzy per-block biome, which left stone inside mountains) and uses the `exterior_floor` output (lowest neighboring surface) to distinguish outdoor faces from buried rock; `BorderPalette` picks deepslate below / patchy snow outdoors around a wandering snowline (average `SNOW_LINE = 214`, `SNOW_BAND = 36`, fading in from Y=179, solid from Y=264; steep faces shed snow), deepslate with ~4% tuff underground.
- **Deepslate basin ("cauldron")**: `BasinMaterialRule` (`cronusfantasyterrain:region_basin`) paints deepslate from Y=0 up to `RegionLayout.basinFloor` (`basin_floor` output) in non-border columns: the floor meets the surface at the mountain foot and curves to Y=0 within `BASIN_REACH` = 384 blocks, so foothills/interiors keep vanilla stone above a deepslate bowl. Below Y=0 is left to vanilla (iron veins).
- **`BorderChunkMaterials`** – queues newly generated chunks on `ChunkEvent.Load`, processes them on server tick (8 per tick, drained on shutdown) to re-apply the palette after neighbor feature spill-over. Only acts when the generator uses `cronusfantasyterrain:regions` noise settings; never rewrites old chunks. Do not query the level/neighbors inside the load callback.

### Invariants

- `region_size` and `border_width` must be **identical** in every `cronusfantasyterrain:region` and `cronusfantasyterrain:biome_terrain` density function (`region_id`, `region_border`, `region_height`, `region_terrain`, `border_exterior_floor`, `region_basin_floor`, `biome_terrain`, `biome_height`, `everwinter_*`), or terrain and region ownership desynchronize (`everwinterTest` checks this).
- The Frozen Wastes pool in `world_preset/regions.json` must match `FrozenLand.POOL_SIZE`/`EVERWINTER_SLOT` (checked by `everwinterTest`). Every pool must list 4–6 biomes, each at most once (`BiomeDistricts.MIN_BIOMES`/`MAX_BIOMES`; codec and `biomeDistrictTest`). Biome terrain must stay zero in border-touched columns, except on Everwinter's side (decisions 24-25): its relief and glacier tongues continue onto the mountain foot on top of the unchanged rock (`everwinterTest` checks it).
- Generation parameters are saved into worlds; verify changes in a **fresh** Fantasy Regions world.
- The code/data key for Scorched Lands is still `ember_lands`; the rename is documentation-only.
- `FrozenLand.REGION_INDEX` identifies the Frozen Wastes pool index.

## Standing user decisions

- **Borders are frozen, all of them** (renewed 2026-10-16 after `update_03_borderfin`). Do not change anything about the region borders unless the user explicitly asks: mountain shape and `RegionLayout` terrain, region partition and rim lobes (`RIM_REACH`/`rimReach`), border width, terrain density outputs, border materials and snow (`BorderPalette`, `BorderMaterialRule`, `BorderChunkMaterials`), the deepslate basin, and the border biome. If biome work inside the regions seems to need a border change, tell the user and wait for their decision. Approved exception (2026-10-17, decisions 24-25): on Everwinter's side its terrain runs up the mountain foot (column logic in `EverwinterColumns`: `borderReach`, `edgeGlacier`; taken-over border columns report `everwinter` = 1, so `BorderMaterialRule` steps aside above the ice-sheet bed and `BorderChunkMaterials` skips them; patchy frost beyond via `BorderPalette.selectFringe`; with no fringe the border palette is unchanged). Never add isolated point features on untouched ground; extend the biome's own terrain.
- Border biome features are restricted to the custom deepslate ore placements; no decorative blocks, vegetation, or other features (enforced by `borderFeatureTest`).
